## 2.0.20 更新范围

相较公开版，本地实测版主要完善了：

- 登录状态分类与错误记录，区分表单未就绪、读取失败、验证码问题和认证跳转。
- 官方二次验证识别与人工接续：需要验证时显示对应窗口，完成后继续当前任务；不自动代发短信。
- 账号隔离、浏览器及受控标签页复用，以及启动、关闭和异常清理。
- 隐藏浏览器情况下的输入处理、单窗口显示／隐藏和主动显示入口。
- 更严格的签到按钮选择、错误传递及结果不明时停止重试。
- 新任务从稳定业务入口重新建立认证流程，避免沿用昨天遗留的验证页面；同一轮人工验证期间不反复刷新。

业务页等待超时后的一次会话恢复在公开 v2.0.2 中已经存在，本次不将它重复列为新增功能。两晚运行记录说明整套流程可用，但尚不能逐项证明每个改动对成功的贡献。

## 使用与限制

以下说明适用于 2.0.20 实测版；公开发行版的功能以对应 Release 为准。

1. 使用本人账号，在程序中保存必要配置，并核对实际考勤时间和页面要求。
2. 保持电脑开机联网、程序运行。定时任务到点执行；关闭主窗口可能只是进入托盘，从托盘菜单选择“退出”才是结束程序。
3. 如学校要求二次验证，在程序显示的官方窗口内由本人完成。需要人工验证的当次任务不计为无人值守成功。
4. 通过状态与日志确认结果，区分本次尝试后成功、此前已经签到、认证失败和业务页面未就绪。已有成功结果时不重复提交。
5. 同一账号只运行一套签到流程；测试独立新工具前先退出旧程序，避免混淆登录、提交和成功记录。

仅记录已核验的个人查寝入口和本机环境，不保证其他校区、客户端环境或学校后续页面变更均兼容。程序配置或页面显示不应替代真实的考勤资格与位置要求。

## 登录态复用仍在实验阶段

独立工具已验证：正常认证后加密保存登录态，关闭原浏览器，再在新浏览器中恢复并查询业务状态。快照失效后，工具可按明确条件尝试一次正常认证；遇二次验证暂停。

**跨天免认证尚未验证成功。** 2026-11-17 的部分快照在当晚或次日上午回到了认证页面；2026-11-18 重新登录后的新快照仅验证了即时恢复。这些实验不属于已安装 2.0.20 的签到实现，也不纳入本次发布范围。

企业微信试验验证的是“宿舍考勤查询”入口，未完成真正的签到链路，已停止作为当前产品路线。不能把打开查询页面计为签到成功。
